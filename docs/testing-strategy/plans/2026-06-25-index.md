# Awskit Testing Grand Plan Index

This directory contains the concrete testing plan split into independent
execution files. Each plan can be assigned to an agent without requiring the
agent to infer ownership from a monolithic document.

## Execution Order

1. `2026-06-25-pass-1-runtime-http-contract.md`
2. `2026-06-25-pass-2-protocol-pbt-and-replay.md`
3. `2026-06-25-pass-3-simulator-stateful-pbt.md`
4. `2026-06-25-pass-4-minio-test-double.md`
5. `2026-06-25-pass-5-ci-release-wiring.md`
6. `2026-06-25-pass-6-fix-failures.md`

## Operating Rule

Passes 1 through 5 are test-construction passes. Agents may make tests fail,
but they must not fix production implementation code. If a test exposes a
product bug, keep the test, record the evidence, and stop that pass.

Production fixes belong only in Pass 6 after failure evidence exists.

When executing from the project-local worktree under `.worktrees/`, run Dune
commands with `--root .` from the worktree root so Dune does not climb to the
parent checkout.

## Failure Evidence

When a test-construction pass leaves a deliberate red test, record it under:

```text
docs/testing-strategy/failures/YYYY-MM-DD-<pass-name>.md
```

Use this shape:

```markdown
# <Pass Name> Failure Evidence

- Command: `<exact command>`
- Exit status: `<numeric exit status>`
- Failing test: `<Alcotest or Dune test name>`
- Observed behavior: `<short, durable summary>`
- Expected contract: `<short, durable summary>`
- Changed files: `<test and docs files changed>`
- Production implementation files changed: none
```
